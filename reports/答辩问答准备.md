# 答辩问答准备（12 个高频问题 + 应答要点）

> 用法：答辩前两人对练一遍。**每人只记 3 个关键词**，不要背稿。
> 原则：**先给结论，再给数字，最后给证据位置**。

---

## Q1　为什么用大模型？传统机器学习不行吗？

**结论**：这个任务的核心难点是「理解语义」，不是「拟合特征」。

**数字**：消融实验里，纯规则特征 P=0.44、R=0.18、F1=0.26；加上语义判别后 P=0.90、R=1.00、F1=0.95。

**为什么**：规则只能匹配"有没有工具""求推荐"这类显式句式，但真实需求常常是隐式的——
比如 GitHub 上一个英文 issue 写 "We grade 2000 proofs per semester manually"，
没有一个中文关键词能命中，但它是典型需求。传统 ML 需要大量标注，而我们只有 120 条。

**证据**：`figs/all/fig_ablation.png`

---

## Q2　阈值 τ=0.36 是怎么定的？为什么不是 0.5？

**结论**：不是拍的，是扫出来的。

**过程**：人工标注 → 对 τ 从 0.10 到 0.90 逐个扫描 → 取 F1 最大的点。

**数字**：τ=0.36 时 P=0.90、R=1.00、F1=0.95。

**为什么不用 0.5**：0.5 是"没有依据的默认值"。τ=0.5 时召回只有 0.61，
意味着四成真实机会被漏掉——对"找机会"这个任务，漏掉的代价比错判高。

**证据**：`reports/threshold_report.md`、`figs/pr_curve.png`

---

## Q3　大模型会不会胡说？你怎么保证结果可信？

**结论**：三道约束，让它只能"打分"，不能"编造"。

1. **结构化输出**：提示词要求只返回 JSON，字段固定（has_need/ai_core/feasible/exclude）
2. **规则兜底**：模型给的类别如果不在附件1 的 16×30 体系内，直接替换为簇内众数
3. **全量落盘**：1434 次调用全部缓存，可按记录编号回放核对

**主动坦白**：我们发现过模型返回"对话问答与知识检索"这种组合词，不符合单选题制，
后来改成"标签取众数 + 脚本校验"才解决。这个坑写进了 AI 使用报告。

---

## Q4　数据采集合规吗？

**结论**：全部只碰公开接口，且主动放弃了不能碰的。

**做法**：
- 只调用官方 API / RSS / 公开搜索页，不登录、不绕验证码
- 请求间隔 ≥1.2s，UA 明示用途
- 原始响应快照存档，可追溯
- **CSDN 的 robots.txt 是 `Disallow: /`，我们直接放弃**

**证据**：`reports/来源探测结果.md`（20 个来源逐个记录 HTTP 返回码）

## Q5　为什么只有 11 个来源？手册有 20 个。

**结论**：20 个全试过，能用的只有 8 个（另 3 个是清单外补充）。

**分布**：8 个可用 / 12 个不可用——
V2EX 网络不可达、36氪和机器之心是 SPA 无 RSS、Kaggle 需登录、Papers with Code 超时、
Semantic Scholar 限流、Product Hunt 需 OAuth、**CSDN 被 robots 禁止**。

**加分点**：这不是"我们偷懒"，是"我们逐个验证过"。论文里这张表本身就是工作量的证明。

## Q6　聚类为什么用 TF-IDF，不用 BERT / BGE？

**结论**：这是权衡，也写在局限里了。

**理由**：TF-IDF+SVD 零依赖、可离线、可解释；BGE 需要下载 300MB 模型、要 GPU 才快。

**诚实说明**：TF-IDF 在短文本上会**低估簇数**，所以聚类结果偏"粗"。
改进路径已写好：配置里换成 `sentence_transformers` 即可，无需改代码。

**数字**：当前轮廓系数 0.06~0.08 偏低，但 **ARI 0.75 说明结构是稳的**——
内部指标低是因为簇内文本本身多样，不代表分错了。

---

## Q7　权重是怎么定的？为什么是这四维？

**结论**：四维来自赛题（多源指向度、记录规模必选，我们补了互动热度和需求强度）。

**权重**：熵权法（客观，由数据离散度算）+ AHP（主观，专家判断）组合，α=0.5。

**为什么组合**：纯客观会忽略业务重要性，纯主观缺乏数据支撑，组合是折中。

**稳健性**：权重 ±10% 扰动 100 次，Spearman 0.998 —— 排序几乎不变。

---

## Q8　"AI 应用机会"的判定标准和赛题四条规则怎么对应？

**结论**：一一对应，且都能计算。

| 赛题规则 | 我们的特征 |
|---|---|
| 真实需求 | 需求句式正则 + 语义打分 |
| AI 是核心 | 能力词表 + 语义打分 |
| 技术可落地 | 排除"自研模型/海量标注/专用硬件" |
| 排除情形 | 六类黑名单（资讯/广告/教程/招聘/政策/吐槽） |

**关键**：不是让模型"自由判断"，而是让它**逐条打分**，再按权重合成——
这样每个结论都能解释"为什么是这个分"。

## Q9　结果能复现吗？别人拿到能跑吗？

**结论**：能，连没有 API Key 都能跑。

**三级降级**：
1. 有 Key → 调 API
2. 无 Key 但命中缓存 → 直接用缓存
3. 都没有 → 退回纯规则

**实测**：把 `.env` 移走重跑，输出与有 Key **完全一致**（735 条 / 52 条机会 / 13 个簇）。

**证据**：源码包里带了 `data/cache/llm_calls.jsonl`（约 680 KB）

## Q10　标注只有 120 条，够吗？κ 是多少？

**结论**：作为"阈值标定"够用，作为"泛化性能估计"不够——我们如实说了。

**数字**：120 条分层抽样，重新采集后 62 条可对齐，P=0.90 R=1.00 F1=0.95。

**主动说明**：分层抽样下指标偏乐观，**该数字用于选阈值，不代表全量性能**。

**κ（一致性）**：工具已就绪，两位队友正在盲标 40 条，标完立即补上。
如果被追问"为什么还没做"，回答：正在做，流程和工具都已验证。

## Q11　系统能处理新方向吗？多久出一批？

**结论**：能，界面上填个方向就行。

**操作**：`发起新需求.bat` → 输入"医疗在线问诊" → 自动采集+分析。

**实测**：医疗 79 条（43 秒）、法律 78 条（完成分析）。四个方向都跑过。

**瓶颈（诚实）**：新方向如果缺少垂直社区，来源只有 2~3 个，机会就少。
这是**来源配置问题**，不是系统能力问题——界面上勾更多源即可。

---

## Q12　你的创新点是什么？

**结论**：三个，都不在算法上，在"怎么用"上。

1. **规则与语义的分工**：规则负责可解释的硬约束（排除资讯广告），模型负责语义理解，
   两者合成一个可解释的置信度——不是"全交给大模型"
2. **阈值数据驱动**：用 120 条人工标注扫 P-R 曲线定阈值，而不是用 0.5
3. **来源可用性实证**：20 个来源逐个探测，形成"来源形态 × 机会密度"的结论——
   **问答社区 47.8% vs 资讯类 0%**，证明选源比调模型更影响产出

**一句话**：我们没有发明新算法，但把"AI 机会识别"这件事做成了**可量化、可复现、可追溯**的流程。
