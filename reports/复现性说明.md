> 结论：**离线模式（`--offline`）下，任意重跑次数、任意机器，四个结果文件逐字节一致。**
> 验证脚本：`python scripts/check_determinism.py --offline`

## 一、怎么重跑

```bash
# 推荐：完全离线，只用随包缓存的模型输出（不需要 API Key，不产生费用）
python run_all.py --track all --batch B20261113-01 --offline --force

# 或者：双击「跑全流程.bat」
```

产物：`data/out/result1.csv ~ result4.csv`

## 二、为什么能保证一致

| 非确定性来源 | 我们的处理 |
|---|---|
| **模型采样随机** | ① `temperature=0`；② 每次调用以「模型+温度+提示词」的 SHA1 落盘缓存；③ `--offline` 强制只读缓存，不发网络请求 |
| **随机初始化** | 所有随机源统一播种 `seed=42`（`seed_everything()`）；SVD、KMeans、稳定性检验、敏感性扰动都显式传 `random_state` |
| **哈希随机化** | 记录编号、赛道 slug 全部改用 `sha1`，不再使用内置 `hash()`（后者受 `PYTHONHASHSEED` 影响，跨进程不同） |
| **文件遍历顺序** | 所有 `glob` 结果 `sorted()` 后再处理 |
| **集合/字典顺序** | 输出前一律排序（如来源覆盖、记录编号列表） |
| **时间戳** | 结果文件不含生成时间；批次号由用户指定而非取系统时间 |

## 四、如果重跑结果和提交的不一样，先查这三处

| 症状 | 原因 | 处理 |
|---|---|---|
| 行数变了 | 重新采集过（内容随时间变化） | 用提交包里的 `data/raw/` 快照，不要再采 |
| 机会数变了 | 阈值或配置被改 | 检查 `config.yaml` 的 `judge.threshold` 是否为 0.36 |
| 编号对不上 | 用旧版脚本重跑过 | 运行 `python scripts/fix_record_ids.py` 迁移编号 |
