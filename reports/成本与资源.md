## 一、模型服务调用成本

| 项目 | 数值 | 说明 |
|---|---|---|
| 累计调用次数 | 1464 次 | 含判别、翻译、主题命名、策划案 |
| 输入 token（估） | ≈ 0.76 M | 按响应长度 × 2.5 反推 |
| 输出 token（估） | ≈ 0.31 M | 按响应字符数 / 1.6 反推 |
| 合计 token（估） | ≈ 1.07 M | — |
| 缓存文件体积 | 962 KB | `data/cache/llm_calls.jsonl` |

**成本控制的三条措施**

1. **全量缓存**：同一条记录重复处理不再调用 API，重跑零成本；
2. **离线模式**：`--offline` 只用缓存，评委复现时**不产生任何费用**；
3. **判别合并调用**：一次调用同时产出四项规则打分 + 两个分类标签，避免 4~6 次分开调用。

> 费用估算请按当期官方价目表 × 上述 token 量计算。论文里建议给出公式而非固定金额，因为模型价格会变。

## 二、存储占用

| 目录 | 文件数 | 体积 | 作用 |
|---|---|---|---|
| `data/raw/` | 142 | 18.3 MB | 原始采集快照（可回原文） |
| `data/clean/` | 44 | 28.9 MB | 清洗判别后的中间结果 |
| `data/out/` | 20 | 10.9 MB | 四份结果 CSV |
| `data/cache/` | 1 | 962 KB | 模型调用缓存 |
| `ui/`（代码） | 9 | 81 KB | 界面 |

单批次 735 条记录的完整数据链路约 **59 MB**，普通笔记本可轻松承载。

**存储上的取舍**

- 原始快照保留（可溯源是赛题硬要求），但按批次分目录，便于单独归档；
- 中间结果（`clean/`）体积最大，可随时由原始快照重算，不需要长期备份；
- 缓存只保留「键 → 响应」，不存完整请求，体积可控。

## 三、运行开销

| 指标 | 实测值 | 说明 |
|---|---|---|
| 全流程耗时（离线） | **19 秒** | 清洗→去重→判别→聚类→评分→导出，735 条 |
| 全流程耗时（在线） | 约 15~25 分钟 | 逐条调用模型，受限速影响 |
| 内存占用 | 约 400~600 MB | pandas + scikit-learn 常驻 |
| 磁盘占用 | 约 200 MB | 含 Python 依赖 |
| 启动时间 | 3~5 秒 | Streamlit 冷启动 |

**为什么离线这么快**：判别阶段不再请求网络，只做缓存查找与打分；聚类与评分本身是秒级计算。

## 四、部署方式与成本对比

| 方式 | 成本 | 适用 | 说明 |
|---|---|---|---|
| 本机运行 | 0 元 | 开发、答辩演示 | 双击 `启动系统.bat`，无需联网（离线模式） |
| 局域网共享 | 0 元 | 同网段多人查看 | 绑定 0.0.0.0，队友用 `http://本机IP:8500` |
| 临时公网隧道 | 0 元 | 评委临时查看 | Cloudflare Quick Tunnel，地址每次变 |
| Streamlit Cloud | 0 元（免费额度） | 长期展示 | 需公开 GitHub 仓库，只读演示 |
| 云服务器 | 约 30~100 元/月 | 长期对外服务 | 需备案（国内），可开采集功能 |

**结论**：本项目按「零成本可演示」设计——离线模式下不需要 API Key、不需要服务器、不需要联网，评委用一台普通电脑即可完整复现全部结果。

## 五、可扩展性

- 单批次 735 条耗时 19 秒（离线）；线性外推到 1 万条约 4 分钟，瓶颈在模型调用而非计算；
- 判别阶段可并发（当前串行以遵守平台限速），加并发后在线耗时约降 60%；
- 存储按批次隔离，新增方向不影响已有批次。
