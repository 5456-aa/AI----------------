## 四、多语言处理（本例的加分点）

英文来源（GitHub Issues、Kaggle）在本赛题里含金量很高——它们是**开发者亲手写的需求描述**，
但直接入表会出现中英混排。本系统的处理是：

1. **不丢弃**：`clean.min_chinese_ratio = 0`，语言不再作为过滤条件；
2. **翻译**：中文占比 < 30% 的记录经大模型译为中文（`pipeline/translate.py`）；
3. **留痕**：原文存 `orig_title` / `orig_content`，语言存 `source_lang`，`translated` 标真假；
4. **可核对**：`来源链接` 始终指向原文，评委可逐条回源。

🔴 **必须重写**（下面这段是骨架，要按你们的真实阈值/真实源改写）：

> 针对英文来源，本文采用大模型翻译后再参与建模，以避免语言过滤导致来源多样性下降；
> 译文与原文一一对应保留（原文见 `data/clean/records.jsonl` 的 `orig_content` 字段与记录来源链接），
> 翻译过程不改变记录的可溯源性。翻译调用全部落盘缓存，保证结果可复现。

**必须诚实交代的两点**（写进 2.4 节）：
- 若提交时未配置 API Key，则英文记录**保留原文未翻译**，此时 `translated=false`，需在论文说明；
- 机器翻译可能引入术语偏差，本系统在审计表中单独统计翻译条数（`reports/data_audit.md` 第三节）。

## 五、合规声明（论文 2.5 节）

🔴 **必须重写**：下面五条是通用模板，要改成你们**实际做过**的事——真实用到的源、真实的间隔秒数、
快照真实存的位置、有没有做 PII 脱敏。写实比写全重要，编造属于违规。

> 本文数据均来自公开可访问内容。采集严格遵守以下纪律：
> （1）不登录、不绕过验证码或反爬机制，仅使用政府/平台公开的 API、RSS 与公开检索页；
> （2）请求间隔不小于 1.2 秒，User-Agent 明示用途与联系方式，遵守目标站点 `robots.txt` 与服务条款；
> （3）仅保存与需求分析相关的公开正文与元数据，对手机号、邮箱、身份证号等个人信息作正则脱敏；
> （4）每条记录保留来源链接与采集时间戳，原始响应快照归档于 `data/raw/`，实现逐条可溯源；
> （5）对反爬机制严格、服务条款禁止采集的站点不予采集，未使用任何非公开数据。

🔴 **必须逐项写实**：用了哪个模型（名称+版本）、哪几处用了、哪些判断是你们自己下的。

| 项 | 本例应写 |
|---|---|

| 使用范围 | 不用于生成论文正文；核心建模思路与实验设计由项目组成员完成 |

| 采纳与修改 | 逐条说明「AI 生成 → 人工如何修改」 |
| 未使用 AI 的部分 | 数据采集合规判断、指标设计、结果解读、论文写作 |

> 赛题原文要求：**明确标注所用工具名称与版本、使用目的，并提交《AI 使用情况说明》**。
